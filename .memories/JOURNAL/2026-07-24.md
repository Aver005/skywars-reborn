# 2026-07-24 — миграция на платформу MgCore

Коммит `7c283ea` «refactor: migrate to shared mg-core minigame platform».
`-3546 / +176` строк, 44 файла. Самое крупное изменение с начала проекта.

## Что произошло

Каркас, который жил в этом репозитории (наследие `mcmgp-template`), **вынесен во
внешний репозиторий** `../kiviuly-mg-core` и стал общей платформой для нескольких
игр (в конфиге ядра видна и вторая игра — `skyblockwars`). SkyWars превратился из
«каркас + игра» в тонкий плагин-потребитель платформы.

Удалено отсюда: `arena/*`, `command/MinigameCommand`, `game/{GameSession,Minigame,
GamePhase,MatchPlayer,MatchResult}`, `listener/{Game,Chat,Protection,Setup}Listener`,
`menu/{Menu,MenuListener,AnvilInputMenu,Arena*Menu}`, `player/PlayerSnapshot`,
`stats/StatsRepository`, `ui/*`, `util/{Msg,Items,Keys,DebugLog}`.

Осталось 13 java-файлов — только правила SkyWars. Таблица «куда что уехало» и полный
разбор смен API — в [../STATE.md](../STATE.md).

## Решения, которые стоит помнить

- **`mg-api` — `compileOnly`, не `implementation`.** Классы контрактов вложены в
  `MgCore.jar`; игровой плагин видит их через classloader ядра (`depend: [MgCore]`).
  Если вкомпилить их в свой jar — будет два набора классов и `ClassCastException`.
- **`includeBuild("../kiviuly-mg-core")`** вместо публикации артефакта. Дёшево и
  быстро, но репозиторий перестал быть самодостаточным: без соседнего клона он не
  собирается. Цена осознанная; если появится CI — придётся публиковать `mg-api`.
- **Своя команда упразднена.** `/sw` больше нет: админка — `/mg` ядра (права
  `mg.admin`), а игровые подкоманды ядро делегирует в `Minigame.onCommand`
  (`kits`, `loot`, `chests <arena>`). `plugin.yml` без секции `commands`.
- **`Msg.merge(this)`** — свой `messages.yml` домешивается в каталог ядра. Отсюда
  требование неймспейса `skywars.*` у всех ключей игры.
- **`Arena.chestSpots` обобщён** до именованных групп точек с тегами:
  `arena.spots("chest")`, теги = id категорий лута. Ровно то, чего требует правило
  «расширяешь ядро — расширяй обобщённо»: теперь любая игра может завести свои точки.

# 2026-07-24 (позже) — соло-отладка: полный сценарий с одним игроком

Задача: для дебага гонять полный матч в одиночку. Проблема: движок завершает матч,
как только живых <= 1 (`GameSession.defaultResult`), поэтому соло-матч закрывался на
первом же тике — капсулы строятся в `onStart`, и следующий же `matchTick` его закрывает.

## Решение (только игра; ядро `kiviuly-mg-core` не трогали)

- `SkyWarsGame` переопределил `checkResult`. Если матч стартовал с ОДНИМ игроком и
  включён `debug.solo-play` (config.yml, по умолчанию `true`), в `onStart` ставится
  флаг `SOLO_DEBUG_KEY` в `Match.data()`, и `checkResult` больше не завершает матч по
  «последнему выжившему».
- Соло-матч завершается только: гибель игрока (живых 0 -> ничья), лимит времени
  (игрок -> победитель) или `/sw stop`.
- Старт соло был возможен и без правок: `/sw start <арена>` (форс-старт) или
  `minplayers 1`. Правка убирает лишь мгновенное закрытие.
- `skywars.solo-debug` подтверждает игроку включённый режим.

## Почему в игре, а не в ядре

`checkResult` — условие победы, а оно по конвенции живёт в `Minigame` (`SkyWarsGame`),
не в игро-независимом ядре. Для всех прочих случаев по-прежнему `Match.defaultResult()`.
Гейт `debug.solo-play` читается из своего `config.yml` (как `exit-guard.*`).

## Проверено

- `./gradlew build` — ЗЕЛЁНАЯ, `build/libs/SkyWars-1.0.0.jar` пересобран.
- `[?]` Смоук в игре не проводился — нужен сервер с MgCore + SkyWars. Ожидаемо:
  `/sw start` с одним игроком -> капсула раскрывается -> ходьба/лут/бой, матч сам не
  закрывается до гибели или `/sw stop`.
